CAP455 - PET ADOPTION MATCHING DESK CA2 TEST CASES
================================

Purpose

These test cases check the CA2 file-handling requirements: - Add and
display Pet and Adopter records. - Search records by ID. - Update an
existing record. - Store records in binary files so data remains
available after restarting the program. - Exercise file reading and
writing using the FileManager functions.

Pre-test setup

1.  Build the program from the src directory: g++ -std=c++11 main.cpp
    Pet.cpp Adopter.cpp FileManager.cpp -o main

2.  Make sure a data directory exists at the location expected by
    FileManager: cap455/data/

3.  For a clean first run, move or back up any existing pets.dat and
    adopters.dat files. Do not delete files containing records you need.

NOTE

The examples below assume the menu choices in main.cpp are: 1 Add Pet 2
Display All Pets 3 Search Pet by ID 4 Update Pet Details 5 Add Adopter 6
Display All Adopters 7 Search Adopter by ID 8 Update Adopter Details 9
Exit

Use IDs that are not already present in your data files. If your menu
differs, follow the equivalent operation.

Important implementation checks

1.  FileManager should write fixed-size record structures containing
    primitive fields and fixed-size character arrays, not raw
    std::string objects.
2.  save operations should append records.
3.  search operations should locate records by ID and return the
    matching object.
4.  update operations should overwrite the matching fixed-size record,
    not append a second copy.
5.  The data directory must exist before opening files unless the
    program creates it.
6.  Check input lengths so text is not silently truncated when copied
    into the fixed-size record arrays.
7.  These tests cover the current Pet and Adopter menu functions. They
    do not test adoption matching or adoption transactions unless those
    features have been implemented separately.
